HARNESSVLA / ROBOCASA

HarnessVLA：真值移除与替代

研究 HarnessVLA 依赖了哪些模拟器真值；逐项去掉，或换成可从真实传感器获得的估计，再观察任务成功率和 Planner 的行为怎样变化。

当前基础：RPent / RoboCasa · GPT-6-Astra xhigh · 32 个 composite 任务 × seeds 1–5

我们要做什么

先沿着实际接口查清楚：哪些信息进入 Agent 上下文，哪些只在控制器或 VLA 内部使用，哪些仅用于最终评分。然后每次改一类信息，比较原版、去掉、替代三个设置。

01 / 原版

建立参照

保留现有真值，记录成功率、动作轨迹和 Agent 实际看到的信息。

02 / 去掉

看它是否重要

逐项切断信息来源，检查返回值、文件读取和内部控制是否仍泄露同类信息。

03 / 替代

看估计能否补回来

用 RGB / RGB-D、机器人传感器或视觉判断代替直接读取模拟器状态。

模拟器真值仍可用于独立评测。需要限制的是被实验移除的信息进入 Agent 或执行过程的通道。

目前在做什么

任务进度真值移除 · 待正确配置验证

目标是去掉观测里的 task_progress，例如食物是否入盘、锅是否回到炉灶。这些中间判据会直接告诉 Planner 哪一步还没完成。

已有一次试跑的 11 次观测未向 Agent 返回该字段，但试跑误用了 DA3 配置，已中止；还没有有效的单变量实验结果。下一步应使用原版深度验证，并单独说明文件读取限制的影响。查看进展与审计 →

接下来怎么推进

  1. 先验证任务进度移除：原版深度、相同模型和预算；核对 Agent 返回与文件通道，验证通过后再跑完整任务集。
  2. 再逐类移除或替代：继续检查几何、抓持／接触、成功信号与评分规则。相机标定和机器人状态单独处理，区分传感器可测量量与特权信息。
  3. 让对比更可解释：固定初始场景和记忆，增加重复运行；每个实验同时保存结果、成功／失败案例及仍然保留的信息。

当前 DA3 对照有初始状态差异，单批结果不能证明每个成败变化由深度替换引起。上述后续工作尚未完成。
