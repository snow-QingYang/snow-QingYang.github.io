02 · 记录单位与字段

一条记录对应一次 Codex 调用尝试（attempt）。一次 episode 可以包含多个 attempt；重启、重试和继续执行分别留记录，并通过同一个 episode_id 汇总。一个 method 调用不等于一次模型请求，不按工具调用次数估算 token。

字段组保存内容约定
身份与来源schema_version, run_id, episode_id, attempt_id, retry_of, thread_id, turn_id；实验批次、task、split、seed、代码提交、SDK 版本、日志相对路径与哈希。启动前生成 attempt ID；重跑同一个 seed 也不能覆盖上一条记录。
模型配置请求模型、实际返回模型（若可得）、provider 标识、service tier、reasoning effort、启动与结束时间、耗时。未知字段保存 null；只存白名单元数据，不导出 key、完整配置或 prompt。
Tokeninput_tokens, cached_input_tokens, cache_write_input_tokens, output_tokens, reasoning_output_tokens, total_tokens，及服务端提供的缓存写入时长分类。cached 是 input 的子集；reasoning 是 output 的子集。保留原始计数及来源，不从字符数推算。
执行与任务结果execution_status：running / completed / timeout / error / cancelled / interrupted；task_success：true / false / null；evaluation_valid、终止原因。Codex 正常完成仍可能任务失败；环境没给结果时用 null，不伪装成有效失败。中间 attempt 的任务结果在有对应环境证据时填写。
完整性usage_status：observed_complete / partial / missing / not_invoked；最后观测时间、终止事件、异常说明。observed_complete 仅指本地观测链完整；不表示已对账。没收到用量是 missing，不是 0。确认未启动 Codex 才是 not_invoked。
费用estimated_cost_usd, billed_cost_usd, cost_status, rate_card_id, rate_source, rate_effective_at，适用费率快照和分项金额。估算和账单分开；未知价格或缺少必要计数时为 null，并写原因。金额用 Decimal 计算。

03 · 怎么采集，失败时怎么保留

启动：创建 attempt→收到 usage：追加事件 + 更新快照→结束：写终止原因与任务结果→汇总：成功 / 失败 / 未知
  1. 从现有 Codex 事件接入。复用 _Recorder.observe()，增加独立的用量落盘通道；保存 SDK 实际返回的 total、last、thread/turn ID 和时间戳。支持当前 SDK 的 snake_case 结构，协议变体在入口显式适配。
  2. 累计值去重，按运行边界算增量。同一 thread 的累计通知不求和；重复通知不增加用量。恢复旧 thread 时记录启动基线，只计本次新增部分。不同 thread 分开计；计数倒退或边界不明确时保留事件并标注异常，不自动当成新开销。验证乱序、compaction、重连行为后再认定有效累计值。
  3. 每次更新都保存。事件文件追加并 flush，快照复用原子替换写入。事件用于恢复、核查与重新计价；金额聚合不会依赖终端输出。会话包含子线程时需验证其用量是否已计入父线程，防止漏记或重复计算。
  4. 所有退出路径统一收尾。普通完成、任务失败、超时、SDK 报错和用户取消都写 usage；不挂在 if success 分支下。CLI 与 Dashboard 使用同一记录逻辑。一次 episode 多次 solve 的费用累计保留，不只留下最后一次 stats。
  5. 硬中断保留已观测部分。进程被 kill 或机器掉电时无法保证收到最后一笔用量。下次汇总检查遗留 running attempt，结合进程退出证据标记 interrupted / partial；从完整 JSONL 前缀恢复。漏掉的服务端用量只能后续对账，不能补成零。

日志中的 provider 内部重试、未回传用量的失败请求，可能未被本地观测覆盖。费用报告始终携带完整性状态；不把本地估算标成实际扣费。

05 · 怎么算钱，报告里怎么看

先保存服务端返回的 token，再用与这次运行匹配的费率估算金额。费率记录 provider、模型、服务档位、生效日期、币种、上下文档位和来源；使用代理时核对代理计费，不能直接把官网价格当成实际账单。官方价格存在不同服务档位与缓存类别，见 OpenAI API Pricing。

普通输入 / 缓存读取 / 输出

当 cache-write 已确认不适用或为 0：
费用 = ((input − cached) × 输入单价
       + cached × 缓存读取单价
       + output × 输出单价) / 1,000,000

reasoning 已含在 output 里，不再加一次。cached 已含在 input 里，也不再加一次。参见 官方 token 字段口径；Codex 具体字段由当前 SDK 事件适配。

有缓存写入费率时

普通输入 = input − cached − cache_write
费用 = (普通输入 × 输入单价
       + cached × 缓存读取单价
       + 各类 cache_write × 对应写入单价
       + output × 输出单价) / 1,000,000

缓存写入按对应费率替代普通输入费率，不能重复叠加。写入数量或类别缺失且会影响价格时，标记不可精确估算。参见 官方缓存计费说明。

每段模型调用按适用费率计算后再求和。不能拿整次 episode 的累计 input 判断单次请求是否进入长上下文档位；需要每次请求的输入长度和实际模型/档位证据。证据不足时先记录 token，将费用标为缺少计价信息。模型重路由或费率变化也按段保留。

报告层级展示内容
每次 attempt 明细任务、seed、模型、开始时间、耗时、执行状态、环境结果、各类 token、完整性、估算金额、费率来源。可筛选成功、失败、未知、超时、重试。
每个 episode最终环境结果、attempt 数、所有 attempts 的 token 与费用之和；单独标记有效性和未知金额数。
每个模型 / 每类任务成功和失败分别列：数量、token 总量、已知费用总额、平均 / 中位数 / P90；另列结果未知、用量缺失和费用未知的记录数。
比较投入产出“成功组平均费用” = 成功 episode 费用 / 成功数；“每获得一次成功的成本” = 全部 attempts 的总费用 / 成功 episode 数（包含失败和重试）。没有成功时显示 N/A；有未知费用时显示已知部分与覆盖率，不能称为完整总成本。

首期统计 Codex 模型 token 费用；RLDX 本地推理、GPU 时长和工具服务费用需另有数据来源。本页实际案例的金额留空，实施时再匹配对应运行日期与供应方费率。

06 · 实施顺序与验收标准

  1. 先做历史补提取。以两套共 320 个已有 episode 目录为样本，生成逐条 token 表、失败表与覆盖率；抽查成功、失败、超时样本，对照 stream 和 transcript。保留来源路径与哈希，不更改历史任务判定。
  2. 再接入在线记录。在 Codex adapter、CLI / Dashboard 和 RoboCasa 结果收尾接入统一记录器，覆盖每次启动及异常退出。
  3. 最后接费用和报告。配置经过核对的费率快照，输出 JSON/CSV；将模型和任务汇总加入 Mobile Astra 工作页面，并链接每条运行明细。
验收场景必须看到的结果当前
任务成功 / 任务失败各跑一个离线事件 fixture，均有独立 usage 记录并关联环境结果；两者都进入总用量。待实现验证
超时 / SDK 报错 / 取消保留已收到的用量和明确终止原因；未获得环境判定时为未知。待实现验证
kill / JSONL 尾行截断能读取最后完整事件或快照；已观测用量可恢复，状态为 partial，不报告完整账单。待实现验证
重复 / 乱序 / 重连 / compaction同一累计值重复到达不增加 token；未见过的旧值也不会覆盖新总量；不明计数倒退进入异常标记。待实现验证
恢复旧 thread / 多次 solve新 attempt 只统计新用量；失败后重试的两条记录都保留，episode 汇总等于各 attempt 之和。待实现验证
没有 usage / 没启动 Codex前者 missing + null，后者 not_invoked + 已知零；报告能区分。待实现验证
缓存与 reasoningcached、cache-write、reasoning 均不重复计算；输入子项超出 input 时拒绝计价并标异常。待实现验证
费用公式 / 未知费率虚构测试费率下：input=1000、cached=800、output=100，单价 10/1/50 美元每百万，cache-write=0 时为 $0.007800；未知费率为 null。待实现验证
批量汇总 / 多进程每个 attempt 独立文件；并行写入不串记录，重复执行汇总不重复记账，已知金额合计可与明细核对。待实现验证
历史 320 个目录目录级覆盖清单包含全部已有结果；单独列异常、缺失与无法定价项，不因失败而跳过。已确认 320 个目录均有 usage 事件；完整补提取待实现

大部分验收可通过真实旧日志和离线事件 fixture 完成，不需要重跑 RoboCasa。接入后再随下一次正常实验核对在线产物；浏览器里勾选方案不等于技术测试通过。
