RPent 感知与真值：接口速查

接口分类整个流程方法内部读取VLA 输入动作反馈

back_project_batch 和 query_world_map 都是几何查询。前者从像素查三维点，后者从空间范围查点簇。点簇没有物体语义标签，具体是什么仍需 Agent 结合图像判断。

按来源区分机器人自身状态、几何、接触和任务判据。RGB 是常规视觉观测，历史记忆是已有经验；两者与当前场景的真值单独区分。

整个流程在哪里访问真值？

  1. 初始化：第一次动作前就保存 step 0 的机器人位姿、夹爪、进度、success，以及 RGB、深度、world map 和相机参数；另生成 success_criteria.md。生成文件不等于 Agent 已经读过。
  2. 观察与定位：view_env_state 读取缓存状态和图像；back_project_batch / query_world_map 查询缓存几何。坐标来源仍是模拟器深度与标定，这条查询链没有调用 SAM3。
  3. 执行动作：脚本控制器使用机器人状态完成运动；VLA 网络接收机器人状态，外围执行器还读取接触与成功信号。具体见下面两节。
  4. 动作后：每次非 readonly 工具执行后自动重新采集观测，向 Planner 回传机器人状态、进度、success、RGB 和动作结果，再进入下一轮；无需额外调用 view_env_state。
  5. 最终评分：finish 只提交 Agent 的结束声明，不查询模拟器。评分读取最后记录的环境 success，文字声明本身不决定成功。

方法内部还读了什么？

下表列工具内部的读取；动作后的统一观测回传是额外路径，适用于所有非 readonly 动作。控制器读过某项信息，并不意味着该原始字段直接输入了 VLA 网络。

方法内部读取与用途
move_to / move_delta
scripted_grasp		使用模拟器末端世界位置完成位置标定与闭环控制，读取夹爪开度维持 hold。move_delta 由当前位置加偏移得到目标；scripted_grasp 组合开爪、移动、闭爪与抬起，本身不调用专门的抓取接触检查。
navigate_to读取底盘世界位置和四元数换算的 yaw，计算方向与距离并闭环导航；也读取夹爪状态。
move_base按固定速度和步数执行。读取夹爪开度维持 hold，执行前后读取底盘位置计算位移；这里的底盘位姿用于报告。
rotate_pitch按固定旋转增量执行，读末端位置用于返回；没有读取当前 pitch 来闭环跟踪目标角度。
set_gripper / release发送固定夹爪指令，随后读回开度；方法本身不调用专门的抓取接触检查。任务中的接触类判据仍可能经自动观测回传出现。
read_text_file按路径读取已有文本，可包括评分源码、状态记录、相机标定 JSON 或历史任务记忆；本方法不查询模拟器。记忆读取受所选任务范围限制，普通文件按路径读取。
write_text_file / list_dir写文件或列目录，不主动查询模拟器，也不触发动作后的自动采集。写入内容仍可能来自之前得到的信息。
reset默认注册，但本轮 evaluation 禁用；返回错误后，框架仍会尝试统一观测回传。
execute_action可选的原生动作接口，当前未启用；启用后同样经过动作后的统一观测回传。

默认注册 18 项工具；其中 reset 在评测中禁用，可执行 17 项。完整手册另收录可选的 execute_action，共 19 项接口说明。

VLA 网络与外围执行器

网络的显式输入：左、右、腕部三路 RGB 历史，环境完整任务语言，以及以下五项机器人状态：
  • state.gripper_qpos：夹爪关节位置。
  • state.base_position / state.base_rotation：底盘世界位置与姿态。
  • state.end_effector_position_relative / state.end_effector_rotation_relative：末端相对底盘的位置与姿态。

rldx_arm 同样接收底盘位姿，只是限制输出的底盘运动幅度。Depth、world map、物体位姿表、接触结果、任务进度和评分源码不直接出现在这个网络输入字典里。

外围执行器另行读取：每个 chunk 后查模拟器抓取接触、对象名和原生 success。接触用于诊断，success 可提前结束本次 VLA 调用；末端高度、夹爪开度与底盘位移也用于生成反馈。这些结果返回 Planner，可影响它下一次选什么动作。

底层环境观测与模型输入的边界

当前环境启用了 use_object_obs=True，reset / step 的原始观测整包传到 EnvClient，未对原始物体通道建立过滤。Planner 状态和 VLA 输入随后按显式字段构造。因此，“没有直接查询物体坐标的工具”不等于“整个系统隔离了物体真值”。

怎么读取动作反馈？

动作返回自动附带 RGB 图像、机器人状态、任务进度和 success；具体动作字段在 log.result 中，例如 log.result.final_dist。也可用 view_env_state() 读取已保存的观测与动作结果，这次查询本身不会重新采集模拟器状态。

自动采集还会保存深度、world map 和相机参数；完整深度／坐标数组不会随每次动作直接送进 Planner 文本上下文，而是供后续几何查询使用。

“目标”是 Agent 传入的坐标。Agent 看图选像素 → 用 back_project_batch 查三维表面点 → 选择目标并调用 move_to(xyz)。final_dist 衡量末端距这个坐标有多远；navigate_to(xy) 对底盘同理。上述两个方法不会自动替 Agent 查询目标物体位置。选错坐标，也可以准确到达；距离小不代表抓对了。

物体三维点和点簇仍需通过几何查询获取。moved、base_drift 只比较底盘起终点，不需要物体位置或目标坐标，也不能说明碰到了什么。

工具的 ok=true 不统一表示“抓到了”或“任务成功”；任务是否完成以环境的 success 为准。

实际例子：PanTransfer seed 2 只主动调用 1 次 view_env_state，但收到 49 次状态观测（初始状态 + 48 次动作回传）；评分源码文件已生成，实际读取次数为 0。
