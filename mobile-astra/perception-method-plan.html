FOUR SOURCES OF PERCEPTION → AGENT METHODS

感知与真值：按四类映射到 method

以当前 RPent RoboCasa 工具为主，把 Agent 能获得的信息按本体状态、视觉语义、几何、交互反馈归类；每个返回字段再注明是模拟器状态、渲染图像、视觉推断还是启发式结果。一个 method 可以携带多类信息。

01 · P

Proprioception

机器人自己现在是什么状态？

末端位姿、夹指开度、底盘位姿；动作后返回的机器人状态。

view_env_state().state

move_to / set_gripper / move_base 等也返回部分本体字段。当前公开 state 没有完整机械臂关节角数组。

02 · S

Visual semantics

场景里有什么，是什么关系？

三路 RGB 供 Agent 判断物体身份、外观与场景关系。

view_env_state() → images

动作后也会附图。当前工具集没有独立 segment / locate；图像里的语义通常由 Agent 判断。

03 · G

Geometry

在哪里，空间范围多大？

像素对应的世界坐标、点簇中心与局部三维包围范围。

back_project_batch()
query_world_map()

使用模拟器深度与相机变换。当前没有直接提供完整物体姿态、抓取方向的独立工具。

04 · I

Interaction feedback

动作是否产生了预期效果？

抓取接触、夹爪受阻、位置到达、移动不足等反馈。

rldx_skill() / rldx_arm()
move_to() / navigate_to()

holding / reached / blocked 是概念，当前没有同名独立工具；证据来自具体返回字段。

图片中的名称是概念接口。robo.state() 对应本地 view_env_state().state；robo.show() 对应其中 images；robo.back_project() 对应 back_project_batch()。robo.segment()、robo.locate() 在当前 RoboCasa Agent 工具中没有一对一实现，不能当成已开放方法。

02 · 信息类别和“真值”是两个维度

四类描述信息说的是什么；来源描述它如何产生。例如“抓住了”可以来自模拟器接触，也可以从夹爪开度推断；两个结果都属于 I，但证据强度不同。物体名字来自接触真值时归入 S 的身份信息，并明确注明它不是视觉识别结果。

来源标签（拟采用）当前例子分类规则
sim_robot_staterobot0_eef_pos、base_pos、gripper_qposP；绝对世界位姿另加 world_frame 标志，便于和编码器/里程计区分。
rendered_rgb / agent_visual_inference相机 RGB；Agent 从图像描述“锅在左边”S。图像暴露不证明推断正确，也不证明 Agent 实际使用了图像。
sim_depth_calibration世界坐标图、反投影点、query_world_map 点簇G；来自模拟器几何与标定，但只描述选中像素/可见表面，不是完整物体坐标 oracle。
sim_contact_oraclegrasp_contact、grasp_obj；Baiyajing supportI；物体名字和关系可同时标 S。记录来源为模拟器接触判据。
derived_heuristicheld_apart、stuck、到位距离判断I，并记录输入来源与判定规则。不能因为结果是布尔值就叫真值。
task_oracle / task_rulesuccess、task_progress、success_criteria.md额外 O 标签：区分环境任务判定、内部进度和成功判定代码。距离等字段按内容再标 G，状态反馈可再标 I。
agent_declared / memoryfinish.status、Agent 总结、seed-0 经验声明和先验不是当前场景真值。保留历史来源，不用于替代环境判定。

O 是附加标签，不替换四分类。如果以后要研究减少真值的影响，必须能独立区分“真实执行反馈”和“环境直接告诉你任务进度”。仅关闭 query_world_map 不代表所有真值通道都关闭了。

03 · 当前 19 个 method 的对应表

下面按method 原生返回字段列标签。实际返回还可能含框架附带观测，分类必须覆盖整份响应。表中“可返回”不意味着每一次调用都有这些字段；错误响应、历史状态和不同动作阶段需按实际内容标注。

动作后自动观测是一个共同入口。Toolkit.execute_tool() 对非 readonly 工具调用 get_env_state()，把原生结果放到 log.result，并返回 state、images、success、task_progress。即使 Agent 不再显式调用 view_env_state，也可能持续获得 P / S / O，以及 log.result 中的 I。异常或被拒绝的动作也可能附带当前观测，不能仅凭执行成功与否决定是否计入。

view_env_state
P · 本体S · 语义I · 交互O · 任务真值
原生返回 / 文件内容		state.robot0_eef_pos / eef_quat / gripper_qpos / base_pos / base_quat；images；log.result；success / task_progress

来源：机器人模拟器状态；渲染 RGB；上次动作结果；环境成功判定

这是混合观测入口。RGB 提供语义推断证据，不直接返回视觉识别出的物体列表。task_progress 还可能包含任务距离等数值，按实际字段补 G。
back_project_batch
G · 几何
原生返回 / 文件内容		results[].world_xyz / valid；summary.median_xyz

来源：模拟器深度 + 模拟器相机变换 → 像素世界坐标图

Agent 选 [row,col]，返回对应可见表面点；median_xyz 不是物体真值中心。依赖像素选择，遮挡与背景会影响结果。
query_world_map
G · 几何
原生返回 / 文件内容		clusters[].center_xyz / bbox_xyz / pixel_count / sample_pixels

来源：同一模拟器深度世界坐标图，经高度/XY 过滤和像素网格分组

返回局部点簇及其范围，不返回物体名称；bbox 不是完整物体尺寸或姿态真值。当前实现不是语义分割。
move_to

来源：模拟器末端状态；目标与末端距离 < tol 的控制判据

ok=true 表示末端位置达到容差；不代表抓住物体或任务完成。ok=false 也不能单独证明碰撞。
move_delta

04 · holding / reached / blocked 要对应到实际证据

概念实际 method 与字段能说明什么不能直接推出什么
holding · 接触证据rldx_*.grasp_contact调用结束时，模拟器 _check_grasp 判定双侧夹指接触某个任务物体。不是视觉判断；也不涵盖所有 fixture 把手。
holding · 开度推断rldx_*.held_apart最后命令要求闭合，且 0.004 < 单侧夹指 qpos < 0.039。无法独立证明持有目标物体；可能夹住其他东西或把手。
现在持有 / 曾经抓到grasped / grasp_detected / grasp_objgrasped = 当前接触或开度启发式；grasp_detected 还包括本次调用历史接触。历史检测为 true 不代表末尾仍在持有；grasp_obj 也可能保留先前物体名。
reachedmove_to / move_delta / navigate_to 的 ok、final_dist末端/底盘位置误差达到对应 tol。不等于完成抓取、放置、倾倒或整个任务。
blocked / stucknavigate_to.stuck耗尽步数预算，且相对起点的移动距离 < 0.12m。不是碰撞真值；未到目标、控制不动和障碍物都可能产生类似结果。
命令执行完成set_gripper / release / rotate_pitch 的 ok相应控制循环执行完毕。不能自动转换成 holding / released / reached_angle。
任务完成观测中的 success；rldx_*.status=success来自环境任务成功判定，标 O。finish(status="success") 只是 Agent 自报，不能替代它。

另一个容易误读的值：rldx_*.peak_lift 用末端 Z 的变化计算，不是物体抬升高度；scripted_grasp.ok 检查动作序列中的到位情况，没有独立的接触成功检查。

05 · Baiyajing 版本也用四类，但入口不同

Baiyajing 的 Planner 输出 vla / pick / carry / put_down / release / goto / retract 等 JSON op，由执行器调用 Python/RPC 方法。下表是其信息入口，不是另加一组可由 LLM 任意调用的工具。还需区分“执行器内部使用”与“送回 Planner”。

类别实现入口暴露层与真值来源
P · 本体env.robot_pose()、Robot._rel()、current_raw_obs模拟器的底盘/末端状态，主要供导航和控制器使用。不能仅因内部访问过就认定 Planner 看过原始数值。
S · 语义Controller.images()；env.scene_info() → Planner._scene_digest()图像送入 plan/replan；objects 名称、lang、initial_fixture、fixture_refs 来自环境场景元数据。后者是语义真值，不是图像识别。
G · 几何scene_info 的 fixtures.pos/size/yaw；env.base_target()；env.check([positions/obj_height/xy_dist/...])地图和 canonical docking pose 供执行器使用；部分设施 XY 进入 Planner digest。positions 主要用于活动监控；不能据此声称全部原始坐标都送给 Planner。why_failed_now、object_locations 可返回距离/高度。
I · 交互Robot.check()/holds()/held_object() → env.check()grasped、support、in_receptacle、inside、on_fixture、door_state 等环境谓词；结果经 summary/history 回传，含 robot_holding、object_locations、why_failed_now。
O · 任务真值get_task_progress / check_success / success code / task_constants任务进度、判定代码和常量进入 Planner；单独标记 oracle 与 rule，不能混作普通 RGB 感知。

核对文件：skillchain/env_plus.py、robot.py、controller.py、planner.py、nav.py，Baiyajing 提交 0596036。scene_info 本身不提供可移动物体坐标，但其他内部谓词及失败解释会提供相关高度/距离信息，分类时逐字段追踪。

06 · 接下来怎么做标注

本期先把分类做成可核查的静态表与离线标注，沿用现有实验日志。若之后要做真值消融，再用这份分类定义开关。

  1. 建立字段级分类表。每项包含 method、field_path、category、source_kind、producer、consumer、坐标系/单位、语义解释和源码证据。单纯 method → category 的单标签不足以表达 view_env_state。
  2. 为旧调用补标签。RPent 以原始 stream/transcript 中实际返回值为准；拆开 state、images、log.result、task_progress、文件内容。Baiyajing 结合 events、Planner 请求载荷和调用链，分别记录 executor_only、planner_visible、visibility_unknown。
  3. 在回放与分析中展示。每次调用右侧显示 P/S/G/I 标签、来源及 O 标记；展开可查看具体字段。按模型、任务、成功/失败统计信息暴露情况，避免把自动附带观测误算为独立主动查询。
  4. 为后续对照实验列清单。分别列出模拟器深度/标定、接触与物体身份、场景元数据、任务进度、成功规则等可控制通道。若要屏蔽，必须覆盖工具响应、自动观测、文件和 prompt 注入；本次不改变权限、不启动消融。

07 · 怎么验收

检查项通过条件当前状态
接口与源码19 个接口完整对应；robo.segment/locate 等概念名不会误标成现有方法。本页静态映射已核对
混合返回view_env_state、rldx_* 按字段分多类；动作后自动观测也被识别。规则已列，离线标注待实现
证据强度contact、held_apart、stuck、ok、success、finish.status 不混淆；缺失字段不补成 false。口径已列，样本验证待实现
信息暴露层Baiyajing 的底层 RPC、执行器摘要与 Planner 输入分开，只有实际进入输入的字段才记 planner_visible。调用链已核对，逐 episode 审计待实现
样本与统计至少覆盖成功、失败、VLA 修复、解析控制、文件读真值和异常响应；源日志能反查每条标签。待实现
多标签计数分别统计调用数、字段类别、自动暴露；同一 method 的多个标签不作为多次调用相加。待实现

当前交付的是分类对应表与实施计划。运行代码、已有实验结果和 token cost 计划都保留；后续标注可离线完成，不需要重新跑 GPU 实验。
