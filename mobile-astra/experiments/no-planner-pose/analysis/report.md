## 与上次实验的区别

E08 和 E09 都关闭主动三维查询、历史任务 / 全局 memory、task_progress、模拟器接触抓取标签，以及成功判据源码入口。两组均保留 RGB、任务描述、当前对话与动作历史、模拟器 success / robocasa_terminated、原生成功早停和最终评分。

E08 仍向 Planner 返回末端与底盘位姿、夹爪状态、实际移动量及动作执行反馈。E09 再移除这些输出：

- 末端与底盘的实测位置和姿态。
- 夹爪开度与 held_apart 启发式。
- final_dist、base_moved、moved、peak_lift、base_drift 等移动测量。
- 动作 ok / stuck / status，实际执行步数、chunks、动作耗时、vla_desync 等执行诊断。

正常 state 和动作 log.result 为空对象；初始无动作时 log.result 可以为 null。限制覆盖初始、当前、历史、动作后观测和保存记录。VLA 与控制器继续使用原有内部 proprioception、历史和执行逻辑。

“不提供位姿坐标”是本组的短名称。实际同时移除夹爪与执行反馈，不能把与 E08 的全部差值归因于位姿坐标。

## 仍可见与内部保留

Planner 仍能获得三路 RGB、相机名称和用途标签、图像索引 step、任务文字、自身发出的命令、错误，以及台面约 0.9 m / 机械臂可达约 0.8 m 等固定先验。success 与 robocasa_terminated 仍可用于判断完成。因此本组不是严格 RGB-only，也不是全部无真值。

Agent 自己提供的 XYZ / XY、夹爪命令、steps 或 finish(status=...) 仍出现在命令历史里；它们不是模拟器返回的实测状态。图像索引 step 也不是实际执行的模拟器步数。

Planner 使用 left / navview / wrist RGB，VLA 使用 256 × 256 的 left / right / wrist RGB。Planner 不接收数值相机内参、pose 或 FOV。内部仍生成 depth、world map 和 camera metadata；深度 / world-map NPZ 沿用最近 25 步保留窗口。既有 memory 语料与源码仍在磁盘，文件读取工具限制不是 OS 沙箱。

Agent 自己的命令参数与 finish 声明不算测量反馈；MCP 框架传输状态 / 调用耗时不纳入机器人反馈字段审计。这是实际轨迹范围内的检查，不是操作系统沙箱证明。

## 有效结果与重试

160/160 局通过结果校验；源码与冻结哈希一致，最终 wrapper / launcher 退出码均为 0。640 份运行、启动、模拟器和 VLA 日志未发现实际 CUDA / OOM / EGL、内存异常或环境—VLA 通信错误混入最终结果。保留 4 次历史 API 断流重连记录。

5 局显存争用中断任务已有效重跑，最终均正常结束但任务未成功；其失败计入分母。更早的 16 份受基础设施错误污染的旧结果已排除，原始记录保留，由有效重跑结果替代。最终 133 个任务失败均保留在统计中。

无日志异常不等于完全没有资源争用。初始任务文字、三路 RGB 与 camera metadata 的比对仅说明保存记录的相等性；E09 的机器人 state 为空，不可用它证明初始位姿相同。相同任务与 seed 也不保证完整初态、动作噪声或轨迹一致。
