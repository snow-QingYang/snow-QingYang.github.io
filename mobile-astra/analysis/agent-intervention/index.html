如何统计

VLA 执行后仍未成功，Agent 再调用非 VLA 的物理动作进行修正，之后由 VLA 或解析动作完成，且本局最终环境评分成功。 只分析截至首次原生成功的动作，避免把成功后的整理动作算作接管。

  1. 已执行过 rldx_skill 或 rldx_arm，此时尚无原生成功记录。
  2. 之后 Agent 调用了非 VLA 物理动作：move_to、move_delta、move_base、navigate_to、rotate_pitch、set_gripper、release、scripted_grasp 或 execute_action。
  3. 随后观测到原生成功，且本局最终评分成功。修正后再由 VLA 完成，以及解析动作直接完成，均计入。

只读查询、文件和 memory 操作、finish 声明、单纯续调 VLA 都不算物理接管。仅在首次 VLA 前采取动作属于“准备后 VLA 完成”。

这是实际执行路径的分类，不能证明没有 Agent 接管就一定会失败。不同批次的初始状态和 VLA 随机采样未完全固定；“仅调用 VLA”仍包含 Planner 对 VLA 的调度，不等同于 E12 Pure VLA。

† E06 未保存逐步原生成功信号，只能统计“VLA → 解析动作介入 → 最终评分成功”；无法排除介入前已经短暂成功，与其他组口径不完全相同。
